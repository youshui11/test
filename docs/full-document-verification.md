# 全文输出遗漏修复验收

本文为历史验收记录。当前聊天已统一由 PD 按需委派 CX/QWJS，原后端预检索、直接全文入口和相关回滚测试已移除；当前调用关系见 `chat-routing-verification.md`。

2026-10-22：用户提问 `09_外观检测相机与追溯接入.pdf中全部内容`，反馈缺少第 3–5 章。

根因：普通向量检索固定只返回相关度最高的 5 个片段，全文请求也沿用该路径，模型无法看到该文件的全部 8 个片段。

修复：明确索取指定文件全文时，通过当前用户和精确文件名（或附件 ID）过滤，按 chunk_index、id 顺序取全部片段并直接流式返回。普通问答保留向量检索。缺少范围、文件不存在、同名多份或全文过长时明确报错，避免返回不完整或错误资料。未改动 agent/server.py。

验证：50 项 Python 测试、9 项 JavaScript 测试通过。新增回归覆盖超过 5 个章节、章节顺序、用户与文件隔离、未知文件、超长内容及通过附件指定范围。真实 PostgreSQL 只读核对目标 PDF 的 8 个片段：输出全部 8 个、逐一匹配、顺序正确，回复 1809 字符；未调用模型或 embedding，未改动原有资料。已重启后端。

## 引文查来源并输出全文

2026-10-22 补充：此前全文路由仅识别直接给文件名的请求，`查询「原句」出自哪篇文档，并输出该文档全文` 会落入普通片段检索。现已增加当前用户/附件范围内的引文匹配，忽略 PDF 提取产生的排版空白；唯一来源按稳定 file_id 展开全文。多来源返回选择提示，未匹配不返回其他用户资料或语义相似资料冒充出处。

以用户实际原句 `空压站仅有总管指针表，支路异常时无法区分设备耗气变化和压力波动。` 验收：来源为 `05_空压站压力与用气监测.pdf`，8 个片段全部返回，与真实 PostgreSQL 内容逐一匹配，回复 1794 字符。未修改数据、未调用模型或 embedding。新增回归覆盖换行空格、多来源、附件消歧和用户隔离。
